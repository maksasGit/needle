# Проверки

Все команды ниже выполняются из `needle-in-a-haystack/`. Это справочник, не разрешение запуска.

По решению владельца от 2026-11-14 и Q-003 автоматические tests/typecheck/build/browser/скриншоты выполняются только по явному запросу. Для документации достаточно прочитать изменения и проверить ссылки. Не объявлять непроведённую проверку успешной; выпуск требует отдельной полной приёмки.

## Уровни и существующие команды

| Уровень | Когда | Команды после разрешения |
|---|---|---|
| 0 — чтение | Документы, небольшие изолированные изменения | Проверка diff и согласованности; без запуска игры |
| 1 — адресная проверка | Типы или навигация | `npm run typecheck`; `node scripts/check-navigation.mjs` для MovementSystem |
| 2 — логика нескольких систем | Экономика, команды, сено, сохранения | `node scripts/check-gameplay.mjs`; сначала устранить известное устаревание сценариев ниже |
| 3 — полный прогон | Запрошенная полная проверка/релиз | `npm run verify`: typecheck → npm test → build → check:build → test:browser |

`npm test` запускает navigation и gameplay последовательно. Оба используют Vite SSR в памяти для импорта настоящего TypeScript; они не требуют WebGL-браузера, но всё равно являются запрещёнными без запроса тестами. `npm run build` уже включает typecheck: отдельно повторять его перед build обычно не нужно. Отдельного актуализированного integration suite пока нет; не изображать gameplay-скрипт таким покрытием.

`npm run check:build` требует существующий `dist`, добавляет THIRD_PARTY_LICENSES.txt и перезаписывает `verification/build-report.json`. `npm run test:browser` требует production build и установленный Google Chrome, сам запускает локальный HTTP-сервер, пишет отчёт/скриншоты. `npm run audit:first-load` тоже использует dist и Chrome, выполняет по три холодных запуска в трёх профилях. Подробности — [PERFORMANCE.md](PERFORMANCE.md).

## Известное устаревание — найдено чтением, без запуска

- `scripts/check-gameplay.mjs` ожидает стартовую вместимость 5 и покупку вместимости за 5 монет; `src/config/balance.ts` задаёт 15 и текущую формулу цены. Позднее тот же скрипт ожидает максимум 80 вместо текущих 615.
- Частичная сборка Game через `Object.create(Game.prototype)` не инициализирует все новые зависимости. Сценарии нужно адаптировать к текущим контрактам, сохранив проверки реальных транзакций, отмены и миграций.
- В `scripts/check-first-load.mjs` зафиксированы старые координаты стога (-1.6, -0.8), а в production — (-5, -5). Дата отчёта также зафиксирована как 2026-11-13.
- `scripts/browser-check.mjs` тоже использует старые координаты в маршрутах и nearEnd-фикстуре; его необходимо актуализировать до полного прогона.
- Исторические результаты в `verification/` не подтверждают нынешний HEAD. Фактический результат нового запуска неизвестен.

Не менять production под старые ожидания и не заменять независимые ожидаемые результаты вызовом той же проверяемой формулы. Обновление сценариев — отдельная задача с разрешённым целевым прогоном.

## Детерминизм и следующие сценарии

Сначала обновить существующие проверки, без нового тестового фреймворка. Сохранить фиксированные шаги времени; Haystack уже имеет свой seed. Для SaleEvent/PigHerd контролировать случайность в тестовом окружении либо согласованным небольшим интерфейсом, не меняя игровые вероятности. Фикстуры сохранений v1–v5 должны иметь независимые ожидаемые остатки сена, исторические расходы, сотые и отдельные источники дохода.

Приоритеты: сбор выбранного ID → заполнение → однократная продажа; покупка/отказ/экипировка; ручное движение и held-vacuum; rare/pig/×2 без двойной выплаты; сохранение/повторная загрузка и старые цены. Для рефакторинга сначала получить эти проверки, затем менять систему.

## Модель и ручная приёмка

`node scripts/export-economy.mjs` генерирует каталог; `node scripts/simulate-economy-v2.mjs` пересчитывает модель и отчёты, `--search` перебирает сетку цен. Требуется Node 22.13+. Это отдельные операции с записью файлов, не тест игры и не доказательство миграций. Предыдущее разрешение симуляции относится к экономической оценке, а не автоматическому прогону после любой правки.

Ручная приёмка: mouse/touch, portrait/landscape, заполнение/сдача/покупка, отпускание пылесоса, пауза/фон, RU/EN/reduced motion, загрузка старого прогресса. Реальный телефон, production и itch.io проверяются отдельно. Результат записывать с датой, версией кода, средой и ограничениями в профильный отчёт `verification/`.
