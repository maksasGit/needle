# Отчёт плейтеста JSON

Обновлено2026-11-17. Реализован формат2, build2026-11-17-playtest-v2. Это расширение прежнего отчёта экономики: старые верхние поля сохранены, общие игровые данные находятся в playtest. Игра/экономика/SaveData v9 не меняют правила из-за включения замеров.

## Как прислать полезный отчёт

1. В настройках включить «Отчёт плейтеста (добровольно)». По умолчанию он выключен; ранее включённая настройка экономики продолжает действовать.
2. Для целого эксперимента начать новый заход с уже включённой записью. Если запись включена посередине или игра загружена из save, отчёт помечается как сегмент, а не полный цикл.
3. Поиграть обычным образом, желательно до победы или до найденной проблемы.
4. До обновления страницы/следующей «Новой игры» открыть настройки → «Скачать отчёт JSON» и прислать needle-playtest.json. Если iframe блокирует скачивание, скопировать JSON из появившегося поля.
5. Вместе с файлом кратко написать, что было неудобно/сломалось и примерно на каком этапе. В JSON нет текстовых комментариев игрока и автоматической отправки.

После reload отчёты не сшиваются: выгружай сегмент перед перезагрузкой. Локальный cache needle.economy-playtest.v1 хранит последний записанный сегмент, но не является архивом всех заходов. Сброс отчёта очищает замеры, сохраняя игру/алмазы/рекорды. Не объявлять current segment доказанным полным прохождением.

## Что собирается и зачем

| Раздел | Данные | Что поможет понять |
|---|---|---|
| Экономика | Время, собранное/проданное, доход по источникам, покупки, поездки, порции и активность свинок, время×2 | Скорость прогрессии, полезность инструментов/свинок, окупаемость |
| Первые действия | Активное время первого сбора, продажи и покупки | Сколько занимает освоение основ |
| Контекст start/latest | Уровни, инструмент, ёмкость/инвентарь, монеты, свинки, стартовые бафы/мышечная память, алмазы/купленное в колодце | Отделить новый заход от продолжения/метапрокачки |
| Правила | Маркер ревизии, число сена, дальность, цены/порции свинок | Не сравнивать случайно разные конфигурации |
| Прогресс | До11 milestone: remaining/activeSeconds на границах10% от startHay сегмента | Где темп ускоряется или игрок застревает |
| Кадры | Среднее/max ms, приблизительный FPS, гистограмма и счётчики>33.4/50/100ms | Частота и тяжесть тормозов; без массива каждого кадра |
| Рендер | Максимальные выборочные draw calls, triangles, geometries, textures | Сложность сцены и рост ресурсов |
| Память | Выборочный peakJsHeapBytes, если браузер предоставляет performance.memory | Возможный рост JS heap, не измерение GPU/всей памяти |
| Запуск | readyMs и initialTransferBytes из существующих замеров первого кадра | Сравнивать время старта; cache/сеть не объявляются cold автоматически |
| Устройство/экран | Только семейство браузера, viewport, DPR, ограниченный touchPoints, язык/reduced motion | Выявить зависимость проблемы от экрана/управления |
| Управление | Число touch/mouse/key/action/joystick и жестов обзора, команд по объектам, прыжков | Каким вводом играют, насколько часто взаимодействуют |
| Затруднения | Отказы по шаблону причины, игнорируемые занятым сбором команды, отмены сбора движением, секунды полной сумки | Где управление/дистанция/ёмкость мешают |
| События | Появление/исчезновение сундуков, сбор/награда, начало/конец×2, алмазы, покупки колодца | Находят ли игроки бонусы, сколько пропускают |
| Обучение/меню | Стартовый/текущий step/done/completed, посещения диалогов, паузы | Где требуется помощь и что отвлекает |
| Стабильность | Счётчики JS/resource errors, unhandled rejection, game-loop error, WebGL loss/restore, save success/failure и сумма времени save | Какие классы сбоев возникают |

## Точность и ограничения

- FPS — по активным интервалам requestAnimationFrame; это не GPU profiler. Меню/фон не входят; редкие большие задержки активной страницы учитываются.
- Renderer/heap снимаются раз в60 отрисованных кадров; пики выборочные, истинный максимум может быть пропущен. Null heap значит «нет доступного замера», а не нулевая память.
- Startup measured текущей загрузки может предшествовать включению отчёта; initialTransferBytes — сумма доступных Resource Timing записей, не гарантированный полный размер холодной загрузки.
- Отказы считаются после общего cooldown: это число показанных объяснений. Команды/ввод — счётчики, не точная запись действий; клавиши не сохраняются по названиям, координаты касаний/путь игрока не пишутся.
- Глобальные ошибки пишутся только пока замеры включены и Game/collector уже созданы. Сбой до создания Game, закрытие вкладки/OS crash и часть WebGL/iframe проблем могут не попасть в JSON. Нет сообщений/stack traces/URL ошибок.
- Это сырые локальные замеры, не результаты тестов и не доказательство стабильности/оптимизации на всех устройствах. Старые симуляцииv2 не учитывают новые метабаффы/порции.

## Приватность и нагрузка

Добровольно, локально, без backend/requests. Не записываются имя, run ID, URL, содержимое localStorage целиком, user-agent целиком, GPU fingerprint, клавиши/координаты/скриншоты/звук или личные комментарии. Семейство браузера определяется локально и экспортируется без исходной строки UA.

Ограничения:200 покупок,200 поездок,64 ключа общих counters,24 шаблона отказов,11 milestones,7 корзин frame histogram; без бесконечного event log и per-frame JSON. При переполнении counters растёт droppedCounters; дополнительные причины идут в otherDenials. Контекст снимается периодически при сохранении/экспорте, а не каждый кадр. Обработчики ошибок снимаются при отключении/dispose. Дополнительных таймеров/сетевых библиотек/ассетов нет. Фактическая нагрузка/размер отчёта пока не измерялись — автоматические проверки не запускались.
readyMs отсчитывается от создания Game до первого render и не включает загрузку HTML/JavaScript до создания Game; это не полное navigation-to-interactive время.
