# Колодец — постоянные улучшения (TEAM-04)

Статус: владелец подтвердил все три группы параметров 2026-11-16. Реализован прототип TEAM-04; ручная приёмка ожидается. Существующие цены за монеты не менялись, эксперимент v2 не активирован.

## Принятый состав

| Улучшение | Эффект по запросу владельца |
|---|---|
| Быстрые ноги | Начальная скорость движения ×1,5 |
| Удачный фермер | Один сундук появляется вдвое чаще: 90–150 секунд |
| Золотое сено | Событие ×2 длится вдвое дольше; нынешнее событие удваивает продажу сена игроком |
| Фермер-любитель | Начинать с граблями |
| Опытный фермер | Начинать с вилами |
| Фермер-профессионал | Начинать с широкими вилами |
| Легенда фермеров | Начинать с пылесосом |
| Друзья | Начинать с одним питомцем; сейчас помощники — свинки |

Алмазы находятся в сене. Колодец открывает отдельное короткое меню постоянной прокачки. Список расширяем через конфигурацию, без переименования уже сохранённых идентификаторов. Форма колодца — оригинальная яркая игрушечная ферма по ART_DIRECTION, без внешних ассетов/обязательных текстур.

## Утверждённый первый баланс

- 20 алмазов на стог, +1 за находку игроком. Свинки не уничтожают алмазы; способ сохранения доступности находки должен быть реализован явно.
- Однократные покупки: ноги 10, удача 15, золотое сено 15, друзья 20 алмазов.
- Последовательная ветка стартового инструмента: грабли 10 → вилы 20 → широкие вилы 35 → пылесос 60. Начинаем с самого высокого купленного инструмента, предыдущие остаются доступны.
- Удача: один сундук каждые 90–150 секунд вместо 180–300; жизнь прежняя, 30 секунд. Одновременно только один сундук.
- Золотое сено: 90 секунд ×2 вместо 45; размер множителя, выплаты свинок/редкостей/сундуков прежние.
- Алмазы и покупки переживают «Новую игру». Покупка действует со следующего захода; текущий не перезапускается автоматически и не теряет прогресс.
- Друзья: одна стартовая свинка входит в общий предел три, не добавляется сверх него.
- Рекорды: старые сохраняются; новые результаты получают сведения о стартовых бафах. Сохраняется общий топ-5 с видимыми значками/доступными подписями стартовых бафов, как подтвердил владелец.

Все три предложения явно подтверждены владельцем. Набор расширяется через config/meta.ts.

## Технические условия реализации

1. Постоянный профиль (алмазы, покупки) отделить от текущего забега. Новый заход сбрасывает только обычный прогресс по существующим правилам; без выдуманного престижа/reset.
2. Зафиксировать набор стартовых бафов в сохранении забега. Покупка будущего бафа не должна менять уже запущенный таймер, инструмент или проверку сохранения.
3. Награды алмазов выдавать по стабильной идентичности и однократно. Учитывать swap инстансов сена, settling, сбор нескольких соломинок, пылесос и поедание свинками.
4. Списание алмазов и покупку сохранять атомарно. Выдача алмаза и отметка получения должны переживать reload без повторного получения. Независимые localStorage-ключи не являются общей транзакцией: требуется восстановимый порядок записи или единый checkpoint.
5. Бесплатные стартовые инструменты/свинка не считаются купленными за монеты. Скорректировать проверяемый coins/spent ledger, не выдавать фиктивный доход и не менять исторические цены старых сохранений.
6. RunClock и рекорды должны фиксировать применённые бафы/правила. Не выдавать старый безбафовый рекорд за сопоставимый новый, не терять завершённые результаты.
7. Диалог колодца ставит игру на паузу; RU/EN, крупные targets, короткие названия/цена/эффект, причина отказа рядом с покупкой. Сбор алмазов даёт видимый +N и использует ограниченный feedback.
8. Один процедурный колодец, один enlarged hitbox, общие геометрии/материалы; меню создаётся по требованию. Не загружать внешние модели/аудио, не вводить 20k отдельных объектов для алмазов.
9. Обновить SaveSystem/migrations, ARCHITECTURE, GAME_REQUIREMENTS, asset lists/budgets/licenses, каталог экономики и правила AGENTS вместе с фактической реализацией.
10. Автоматические тесты/build/browser/screenshots не запускать без просьбы владельца. Ручная приёмка должна покрыть старые saves, reload при находке/покупке, новый заход, каждую ветку, бафы сундуков/×2 и рекорды.

## Фактическая архитектура и ограничения

SaveData v8 включает постоянный MetaProfile (earned + bought), snapshot бафов текущего захода и GemState (20-битная маска + максимум 20 позиций выпавших алмазов). Остаток алмазов вычисляется как earned минус стоимость подтверждённых покупок. Все данные, удаление сена и факт находки записываются одним localStorage.setItem; отдельного несогласованного ключа профиля нет. New Game переносит профиль, не удаляет старый save заранее и заменяет его новым checkpoint после первого кадра. Если сохранение недоступно — общий видимый статус, прогресс остаётся в памяти вкладки.

Алмазы привязаны к стабильным ID соломинок 500 + 1000 × i, i=0…19. При сборе игроком начисляются автоматически, также можно подобрать видимый алмаз напрямую. Свинка оставляет находку на земле у точки еды; позиции и маска сохраняются, повторной выдачи нет. Для старых saves уже отсутствующие соломинки считаются пропущенными, ретроактивные алмазы не начисляются; в оставшемся сене находки доступны. Старые текущие заходы получают пустой snapshot бафов, покупки действуют при следующем New Game.

Бесплатные стартовые инструменты и первая свинка вычитаются из расчётных расходов текущих покупок, без фиктивного дохода. Это не меняет исторические цены/legacy baselines. Таймеры событий получают множители только из snapshot захода. Колодец (9, 8), препятствие с enlarged target, создаётся после первого кадра; меню ленивое. Алмазы — два InstancedMesh по 20 слотов, обновление позиций 10 Гц. Новых внешних assets/dependencies нет.

Автоматические проверки, сборка, браузер и скриншоты не запускались. Симуляция v2 не учитывает этот метаслой. Условие победы прежнее — одна иголка. Престиж и новые метаскины не реализованы.
